# Input schema

CSV is UTF-8 with header. Paths in JSON resolve relative to the configuration file. The three tables contain eligible candidates, including failed or missing predictions. Use stable unique IDs. Preserve the membership/provenance files, source status, structural correspondence and method comparison design with your study; they are not inferred by the calculator.

`units.csv`: `unit_id`, `family`, `observed` (finite pKd). Include all units for absolute evaluation. IDs in linked analyses are deduplicated automatically. If supplying no absolute predictions, the endpoint labels are still needed to verify observed pair differences.

`pairs.csv`: `pair_id`, `family`, `landscape`, `position`, `wt_unit_id`, `mutant_unit_id`, `observed_delta`. Family must agree with both units. Landscape IDs need only be unique within family. The pair is an explicitly curated same-experiment link; `observed_delta` must equal mutant minus WT within `delta_tolerance` (default 1e-8). Provide a separate candidate table for structural position controls. A landscape may have multiple substitutions per position.

`predictions.csv`: `method`, `seed`, `member_id`, `status`, `value`, `checkpoint`. `member_id` is a unit ID for `endpoint`, a pair ID for `direct` or `score`. `status=success` and finite numeric value are required for inclusion; other status or nonfinite values are missing. Each method/seed/member key is unique. For endpoint predictions, both endpoints of a pair must have identical nonempty `checkpoint` (the fold/checkpoint or predetermined fixed-ensemble identity); values already in common pKd units. For direct predictions supply aligned pKd differences. For `score`, supply the already direction-aligned mutant-minus-WT native score; no pKd conversion is performed. `checkpoint` for direct/score records provenance. Exact zero is retained. `zero` is a built-in reference and has no prediction rows.

JSON fields: `units`, `pairs`, `predictions`, `unit`, `direction`, `reference`, and `methods`. Each method has `type` (`endpoint`, `direct`, `score`, `zero`), nonempty `seeds`, `identity`, and optional numeric `multiplier` for an explicit documented sign or scale conversion before scoring. Score multipliers change only native score/sign, not its physical dimension. List seed labels exactly as in CSV. A fixed ensemble uses one seed label and one predeclared ensemble identity; OOF models list each seed separately. Optional `min_positions` defaults to 5; `rank_methods` defaults to all except zero; bootstrap draws/seeds default to the CoPRA settings described in the protocol. `reference` names a method and effects are reference minus method. Mixed score and pKd methods share members but only dimension-compatible metrics are computed.

JSON contains family-level values and paired contrast intervals; coverage includes candidate, method-success, shared and local counts, per-method rank denominator, and common-defined rank landscape/family counts. Method-specific ranking averages defined landscapes; use `rank_common_metrics` for a shared-defined comparison. Absolute comparisons use all declared endpoint methods, independently of direct/score success, and linked absolute scopes use shared pairs. Report the cohort and denominator for every comparison. Bootstrap contrasts are provided for pair metrics on families with all required values; absolute MAE includes family-bootstrap intervals. Missing information is represented by JSON null or absent metric, never zero.

Optional extra columns can preserve source-record IDs, experimental WT-link evidence, construct and structure correspondence statuses, exclusion reasons, and configuration references. They travel with the input tables but are not adjudicated or output by the calculator; qualification is performed before supplying the candidate members.

Ranking contrasts and their family-bootstrap intervals use the intersection of landscapes defined for every `rank_methods` method and every declared seed; their landscape/family counts and family order accompany the contrast. If this intersection is empty, no ranking contrast is emitted. Each method’s own rank mean remains descriptive. The bootstrap is resampled over families represented in the common ranking scope.

`multiplier` must be a finite JSON number (not a string or boolean). Converted predictions or endpoint differences that are nonfinite, or exceed sqrt(float64 maximum)/4 in magnitude, are treated as missing to keep squared-error arithmetic within a conservative numeric range; exact zero remains a valid prediction.
